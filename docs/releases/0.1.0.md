# work-fold 0.1.0

work-fold 0.1.0 is the first public release under the new product identity. It
is a local-first desktop workspace for working with an AI Assistant across
ordinary folders, with explicit context, visible authority, and durable
background work.

This is a new application, not an in-place update from Workspace. It installs
beside the legacy app, starts with an empty work-fold profile, and deliberately
does not import, migrate, rewrite, wipe, or delete legacy Workspace state or
`.workspace/` metadata.

## A quieter, folder-first work surface

- Each **Space** is backed by an ordinary folder. Registering an existing
  folder does not move, copy, or rename its files.
- Files, Chats, History, Space-owned Library tabs, and Space-owned Assistant
  tools tabs stay bound to their exact Space.
- Inactive Chat tabs remain mounted while turns run. Switching tabs,
  minimizing, sleeping, waking, or closing the main window to the tray does
  not silently cancel accepted work.
- The folded-sheet visual identity, graphite-and-paper palette, compact native
  chrome, onboarding, About surface, app icons, DMG artwork, and management
  popover all use the new lowercase work-fold brand. Light, dark,
  high-contrast, and reduced-motion presentations are covered.

## Assistant tools and local apps

- Skills and Extensions remain native Pi resources and are managed together
  through **Assistant tools** without inventing a work-fold-only package
  format.
- Agent-created local apps remain in a separate reviewed web lane. Installation,
  file and destination grants, connections, notifications, and each named
  automation are separate decisions with explicit revocation.
- App Releases and artifacts use strict, content-addressed work-fold contracts.
  Older branded registries, stores, bridges, routes, and payload aliases are
  rejected rather than silently imported.
- Local-app storage, connections, schedules, receipts, and authority are
  Space-scoped and fail closed when their reviewed identity changes.

## Management and Checks

- The native menu-bar/tray popover provides a compact management conversation
  above all Spaces, including bounded file references, honest child-task
  outcomes, explicit request lineage, Stop, and durable history.
- The installed `work-fold` CLI provides compact read-only context plus a
  separately authenticated act lane for Chat, management, Space, file, and
  optional Check operations.
- Optional Checks inspect only explicitly designated, bounded files. They do
  not create an ambient scanner, dashboard, background schedule, automatic
  fix, or permanent navigation item.

## Clean-break and data safety

- New portable Space metadata lives under `.work-fold/`; legacy `.workspace/`
  content is hidden and excluded but remains byte-preserved and non-authoritative.
- New machine state uses independent application profiles, protocol paths,
  updater caches, credential service names, and Pi session paths under
  `sessions/work-fold/`.
- Pi personal authentication and personal resources may remain shared through
  Pi itself. work-fold does not copy legacy product credentials into its own
  credential namespace.
- Uninstallers do not delete application data automatically, and managed
  folder removal fails closed when legacy metadata could make recursive
  deletion unsafe.

## Current limits

- Google Drive folders work through Google Drive for desktop; this release does
  not claim native Google Drive API integration.
- Package review, restricted-app permissions, connection credentials, and Chat
  context remain separate grants. Installing a capability does not silently
  add files or account access to a Chat.
- The first work-fold install is manual. Automatic-update continuity is proven
  only by installing this release and then updating to a later work-fold
  version; no Workspace build is an updater predecessor.

## Verification

The release-candidate source gate contains 680 tests: 679 passing, one expected
Windows-only skip on macOS, and zero failures. TypeScript checks, a
high-severity dependency audit with zero known vulnerabilities, desktop
preparation, the real-Electron restricted-app sandbox probe, canonical Windows
packaging, macOS structural packaging, clean-profile/coexistence tests, and
real-size light/dark/accessibility visual review are included in the release
evidence. Public artifacts are accepted only after their platform signing,
checksums, updater metadata, and installed behavior are independently verified.
