# Workspace 0.4.15

Workspace 0.4.15 hardens Chats against provider streams that stop after work
has already begun.

## Safe provider recovery

- OpenAI-compatible providers that terminate a started stream with the generic
  `finish_reason: error` now enter Pi's bounded transient-error retry path.
- A retry removes only the failed assistant attempt and continues from existing
  tool results. Completed tool calls are not replayed.
- Failed-attempt text is cleared before replacement output streams, so the Chat
  does not concatenate abandoned and recovered answers.
- Retry progress is reported in the existing Assistant activity surface.

## Durable interrupted turns

- If the retry budget is exhausted, Workspace appends the latest partial
  response to the Space's portable `.workspace/conversations/` transcript.
- The interrupted message records the retry count, provider, model, and latest
  state of completed Assistant activity.
- The Chat renders that record with a clear interruption marker instead of
  replacing the turn with a generic red banner.
- Workspace keeps the settled Pi session alive, allowing the next user message
  to continue from the surviving conversation and tool results.

## Model disclosure

- A new Chat now shows its configured provider and model before the first
  message is sent.
- Existing Chats continue to show their live model and context-window state once
  runtime usage is available.

## Upgrade notes and boundaries

This is an in-place update. Registered Spaces, named Chats, ordinary files,
Library materials, History, Pi resources, provider credentials and selection,
appearance settings, restricted apps, grants, connections, automations, app
data, and App-platform state are preserved.

The new durable interruption record applies when Workspace receives and settles
a terminal provider error. It does not claim to journal every token across an
operating-system process kill or forced machine shutdown. Existing background
turn, sleep/wake, close-to-tray, and normal quit protections remain unchanged.

## Release verification posture

Public release completion requires the exact pushed `v0.4.15` commit to pass
Node 24 dependency installation, TypeScript checks, the complete 576-test
suite, high-severity dependency audit, desktop preparation, the real-Electron
restricted-app smoke, the canonical Windows package and public source release,
and the guarded Developer ID-signed, notarized, and stapled macOS publication
lane. The installed 0.4.14 macOS app must discover and apply 0.4.15 through the
official public update feed, after which installed-bundle verification must
confirm the production bundle id, signing team, notarization staple,
Gatekeeper acceptance, and updater metadata.
