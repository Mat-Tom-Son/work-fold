# Workspace 0.4.3

Workspace 0.4.3 is a focused frontend reliability and accessibility release.
It keeps Chat context and Assistant settings attached to the exact place the
person chose, fixes generated Chat titles, and makes every major desktop modal
behave consistently from the keyboard.

## Safer Space-bound Chat context

- Attaching a file now targets one exact Chat tab in one exact Space.
- Switching Spaces or returning to another mounted Chat no longer replays an
  old attachment request into the newly active conversation.
- Background Chats remain mounted and continue running, while their context
  stays isolated from the active Space.

## Stable Assistant and Chat state

- Loading Pi's provider catalog preserves the already configured provider and
  model instead of silently replacing the model with the catalog's first item.
- Changing providers still selects the first valid model for the newly chosen
  provider when the previous model is unavailable there.
- The historical `New Chat` seed is treated as a placeholder, so an
  Assistant-generated conversation title can appear in Chat lists and tabs.
- A later intentional rename to `New Chat` remains authoritative.

## Keyboard and interface polish

- Settings, keyboard shortcuts, Space creation, file version history, and the
  command palette now share one focus-containment and background-isolation
  contract.
- Focus enters each dialog predictably, wraps in both directions, ignores the
  page behind the dialog, and returns to the invoking control after close,
  including under React Strict Mode.
- The renderer no longer emits the Chromium warning caused by an unsupported
  meta-CSP directive, and local development no longer requests a missing
  favicon.
- Capability discovery now accurately explains when npm reported more matches
  than Workspace's bounded catalog window.

## Upgrade notes

This is an in-place update. Registered Spaces, ordinary files, Chats, Library
materials, History, Pi resources, provider credentials and selections,
restricted apps, grants, connections, automations, and App-platform state are
preserved.

No new permissions are introduced. Existing file attachments remain explicit
Chat context; the release narrows delivery so a request cannot follow the
person into another Space or tab.

## Release verification posture

The 0.4.3 candidate was exercised through the installed frontend with realistic
files, content search, version restore, Library copy, Chat lifecycle controls,
background turns, a real provider-backed Skill, settings, updater checks, and a
complete restricted-app build, preview, local Release, cross-Space install,
storage-isolation, uninstall, purge, and Release-deletion cycle. Source-browser
regression checks additionally verified exact cross-Space attachment isolation,
configured-model preservation, responsive settings layout, modal focus
containment, and a clean console.

Public release completion requires the exact pushed `v0.4.3` commit to pass
Node 24 TypeScript checks, the full test suite, dependency audit, desktop
preparation, the real-Electron restricted-app probe, the canonical Windows
package/release gates, and the guarded Developer ID-signed and notarized macOS
publication lane. The installed 0.4.2 macOS app must then discover and apply
0.4.3 through the visible frontend updater button, relaunch, pass
installed-bundle verification, and survive a full quit and cold reopen.
