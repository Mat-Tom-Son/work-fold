# Workspace 0.4.4

Workspace 0.4.4 is a focused navigation and Assistant-tools release. It removes
an administration-heavy destination from the primary rail, gives Skills,
Extensions, and Space apps room to breathe in the work area, and makes adding
reusable material or Assistant functionality feel like one coherent action.

## A calmer primary rail

- The primary rail now stays focused on Files, Chats, Library, and History.
- A new **Add** menu opens Library materials, Skill and Extension discovery,
  app building, or installed Assistant-tool management from one predictable
  place.
- The menu supports initial focus, roving arrow-key navigation, Home, End,
  Escape, outside-click dismissal, and focus restoration.
- Existing desktop commands, keyboard shortcuts, and command-palette actions
  continue to open the corresponding Assistant-tools view.

## Assistant tools in the work area

- Installed and Discover now live in one persistent, Space-owned
  **Assistant tools** tab rather than a narrow navigator pane.
- Installed items clearly distinguish **This Space** from **Personal** scope,
  while retaining package provenance, load state, diagnostics, updates,
  removal, and core-tool detail.
- Apps in the current Space appear before Skills and Extensions with a compact
  empty state and direct routes to Chat or App Studio.
- Search, type, scope, and sort controls use a quieter toolbar, while Skills,
  Extensions, apps, and catalog entries use responsive divided lists instead
  of nested administration cards.
- The tab restores safely across launches, remains bound to its owning Space,
  and preserves the selected Installed or Discover view.

## Library and authorization stay explicit

- Library remains the home for passive reusable files. Assistant tools remain
  separate because Skills, Extensions, packages, and restricted Space apps can
  carry executable behavior or authority.
- Opening Library does not install a tool or attach content to a Chat. Installing
  or importing a tool still requires its own explicit action and scope.
- Space-app network, file, notification, connection, automation, data, update,
  and removal controls remain host-owned in Assistant tools.
- No new permissions are introduced by this release.

## Responsive and accessible polish

- The layout now adapts to the actual Assistant-tools container, including
  compact split-pane and horizontal-shell widths, without squeezing explanatory
  copy into an unreadable column.
- Light and dark themes use the same restrained hierarchy, with one prominent
  add action and quiet secondary controls.
- Details and add dialogs retain modal focus containment and return focus to
  their invoking control.

## Upgrade notes

This is an in-place update. Registered Spaces, ordinary files, Chats, Library
materials, History, Pi resources, provider credentials and selections,
restricted apps, grants, connections, automations, and App-platform state are
preserved.

An older saved Capabilities rail selection safely falls back to Files. Existing
Assistant-tool tabs are created only when opened, remain Space-bound, and do not
change installed resources.

## Release verification posture

Public release completion requires the exact pushed `v0.4.4` commit to pass a
clean Node 24 install, TypeScript checks, the full test suite, dependency audit,
desktop preparation, the real-Electron restricted-app probe, the canonical
Windows package/release gates, and the guarded Developer ID-signed, notarized,
and stapled macOS publication lane. The installed 0.4.3 macOS app must then
discover and apply 0.4.4 through the visible frontend updater button, relaunch,
pass installed-bundle verification, and survive a full quit and cold reopen.
