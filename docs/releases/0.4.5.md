# Workspace 0.4.5

Workspace 0.4.5 makes Library feel like part of the work canvas instead of
permanent navigation. It also tightens the shared contributor contract used by
Codex and Claude Code.

## A simpler rail and a clearer Library

- The primary rail now stays focused on **Files**, **Chats**, and **History**.
- **Add or manage** opens Library, Skill and Extension discovery, app building,
  or installed Assistant-tool management from one predictable menu.
- Library opens as one persistent, Space-owned tab per Space. Activating a tab
  restores its owning Space.
- Every Library tab reads the same personal collection. The owning Space is the
  default copy destination, while an explicit selector can send an independent
  copy to any registered Space.
- Reopening Library from Add resets the destination to the owning Space, and
  duplicate Space names include their folder path in the selector.
- Older saved Library rail state migrates into the new tab instead of silently
  falling back to Files.

## Safer, calmer Library actions

- Library gets the full work canvas with a responsive tree-and-detail layout,
  clear scope copy, and earlier compact breakpoints.
- Top-level **Add files to Library** and **New Library folder** actions always
  target the Library root, so a previous selection cannot redirect them.
- Search, item selection, and destination changes pause while a copy is
  running, preventing mismatched success messages.
- Adding or creating content refreshes one shared collection state, so Library
  tabs in other Spaces cannot become stale.
- Copying remains explicit, creates ordinary files under **From Library**, and
  never attaches content to a Chat automatically.

## One contributor contract

- Root `AGENTS.md` remains the canonical product, test, and release contract;
  root `CLAUDE.md` imports it rather than duplicating it.
- Codex and Claude Code use the same npm scripts, tests, release lanes, native
  Pi Skills, Extensions, built-in tools, and catalog.
- Workspace-owned product documentation and the restricted-app lane remain
  harness-neutral. No alternate harness-specific formats or policies were
  introduced.

## Upgrade notes

This is an in-place update. Registered Spaces, ordinary files, Chats, Library
materials, History, Pi resources, provider credentials and selections,
restricted apps, grants, connections, automations, and App-platform state are
preserved. No new permissions are introduced.

## Release verification posture

Public release completion requires the exact pushed `v0.4.5` commit to pass
Node 24 TypeScript checks, the full test suite, dependency audit, desktop
preparation, the real-Electron restricted-app probe, the canonical Windows
package/release gates, and the guarded Developer ID-signed, notarized, and
stapled macOS publication lane. The installed 0.4.4 macOS app must then
discover and apply 0.4.5 through the visible frontend updater button, relaunch,
pass installed-bundle verification, and survive a full quit and cold reopen.
