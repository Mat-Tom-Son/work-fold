# Workspace 0.8.0

Workspace 0.8.0 brings optional, evidence-backed **Checks** into the desktop
without turning them into a dashboard, permanent navigation item, background
watcher, or ambient scan. A quiet signal at the Files edge appears only for a
Space with deliberately configured Checks and opens one reusable Space-owned
work tab.

Checks still inspect only the exact files or bounded targets a person chose,
run only when a person or authenticated agent requests a run, and remain absent
from every unconfigured Space.

## Quiet Files integration

- The Files toolbar shows a compact conditional Checks signal. It distinguishes
  proposed-only, never-run, stale, running, needs-attention, Check-health,
  temporarily unavailable, and current states without moving the main rail.
- A current admitted finding adds one subtle marker to its exact designated
  file. A containing folder may carry a smaller propagated marker so a finding
  remains discoverable while the tree is collapsed.
- Markers disappear when evidence is stale, decided, invalidated, unavailable,
  or no longer current. Workspace does not use filename colour, editor
  squiggles, green success badges, automatic panel opening, or notifications.
- Mixed freshness remains honest: when one Check has never run and another
  prior result is stale, the surface reports both kinds of uncertainty instead
  of hiding one behind the other.

## One Space-owned Checks work tab

- Selecting the Files signal opens one canonical **Checks** tab owned by that
  exact Space. Switching Spaces never silently retargets it.
- The tab separates current re-verified findings, Check-health problems, and
  designated expectations. Infrastructure failures are explicitly not labeled
  as problems in a person's files.
- **Run Checks** is the only way the desktop starts sensor work. Opening the tab
  re-verifies recorded evidence but never runs a sensor. Accepted runs expose
  **Stop**, retry transient task polling with bounded backoff, and share the
  same task and authority fences as the management CLI.
- Fingerprint-scoped **Mark resolved**, **Tomorrow**, and **Not an issue**
  actions use the same decision path as agents and the CLI. A stale decision
  refreshes the tab instead of leaving an obsolete finding actionable.
- Returning focus or visibility to Workspace refreshes the relevant aggregate
  or open work tab so management/CLI actions become visible without adding a
  file watcher or automatic Check run.

## Fail-closed edge hardening

The release received parallel adversarial reviews over the renderer, service,
filesystem authority, concurrency, and release path. The resulting fixes make
the uncertain states deliberately boring and explicit:

- A failed content-bearing refresh suppresses cached health claims, finding
  counts, cards, decisions, target details, and truncation copy until Workspace
  can re-verify them. Run remains disabled while current truth is unavailable.
- A decision rebinds its finding to the current declaration, local grant,
  sensor implementation, and designated evidence immediately before storage.
  Changed evidence returns a typed conflict; identical still-current decisions
  remain storage-idempotent.
- Terminal-persistence recovery is bound to the originating Space. Polling the
  same task id through another Space cannot finish the run or release its
  capability fence.
- Run-all now supports the complete bounded 256-authority ceiling instead of
  accepting a 65th valid Check and failing only when the run record was stored.
- Immediate renderer mutation locks prevent rapid duplicate Run, Stop, or
  decision submissions before the first response arrives.

## Optional boundary and current limits

- There is no primary-rail item, permanent badge, automatic creation,
  background schedule, proactive notification, gate over other work, model
  sensor, or automatic fix.
- A proposal remains inert. Enablement is still an explicit authenticated
  management/CLI action bound to one Space and one exact declaration digest;
  the desktop work tab reviews authority and results but does not silently grant
  it.
- The installed `workspace.file-presence@1` sensor checks present/absent path
  state across ordinary file types. It does not inspect text, dates, totals,
  citations, images, spreadsheet cells, or document structure. Future sensors
  must reuse the same bounded-target and evidence-admission protocol.

## Upgrade notes

This is an in-place update with no manifest or user-data migration. Existing
Spaces, files, declarations, enablement grants, run history, findings,
decisions, Chats, management conversations, History, Library materials, Pi
resources, credentials, restricted apps, App Projects, Releases, Instances,
and appearance state are preserved.

An unconfigured Space behaves exactly as before and is not scanned. Existing
configured Checks gain the conditional desktop entry point, but no sensor runs
until a person or authenticated agent explicitly requests one.

## Release verification posture

The final Node 24 source gate contains 659 tests: 658 passing, one expected
Windows-only skip, and zero failures. It includes the adversarial regressions
for stale evidence decisions, wrong-Space terminal recovery, the 65-Check
boundary, repeated decision idempotence, cached nonempty/truncated outage
truthfulness, six consecutive task-poll failures followed by recovery, rapid
duplicate submission, stale 409 refresh, focus refresh, mixed freshness, and
Space-owned tab behavior.

The release lane also runs TypeScript checks, a high-severity dependency audit,
desktop preparation, the real-Electron restricted-app sandbox probe, canonical
Windows packaging, and the guarded macOS signing, notarization, stapling,
checksum, manifest, digest, and public-feed verification.
