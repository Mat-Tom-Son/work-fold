# work-fold 0.4.23

September 7, 2026

Space apps can now ask their owning Assistant to do a named task. Review the
instructions and input in Apps, run it in that Space, and open the resulting
Chat. The app receives its own task status and bounded reply. Space apps can
also display results from a Check you explicitly select in their access controls.

Change this app starts from the exact installed version, creates a working copy
with History, and prepares an Assistant draft. Review a preview or release update
before applying it. Preview and installed versions can coexist with separate data.
App data can be exported, restored to its matching installation and revision, or
recovered with Undo after clear or restore.

The web fold opens bounded file previews and reviewed app views. Completed
requests link directly to copied files, observed child-task outputs, installed
apps and pending reviews. Approved browsers can review and run declared app
worker actions outside the app frame. Receipts survive reconnects without
replaying accepted writes; shared viewers remain read-only. The desktop must
be online to execute work.

Live testing also fixed stale Space and app menus, nested-dialog navigation,
expired browser-session recovery and offline request churn. Text-review guidance
now checks the meaning of a criterion before making wording complaints. Existing
text Checks require explicit re-enablement after this sensor change; their
files and declarations are preserved. Model suggestions remain fallible, and
malformed model output remains a visible Check error rather than a clear result.

Verification includes the complete desktop and bridge suites, real Electron
sandbox probes, signed native UI testing, a real-model comparison and Check
failure/repair with a two-Space handoff, and paired phone-sized browser worker,
retry, restart and offline tests. Details are in docs/apps-fold-workflows.md.
