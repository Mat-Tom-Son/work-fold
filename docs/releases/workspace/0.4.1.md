# Workspace 0.4.1

Workspace 0.4.1 is a focused quality-of-life release for Chat organization,
runtime awareness, and Assistant setup. It adapts useful workbench patterns from
T3 Code to Workspace's local-first, provider-neutral product model without
copying T3's runtime architecture or turning Workspace into a code-only app.

## Chat lifecycle and background work

- Chats now have **Active**, **Snoozed**, and **Archived** views with counts,
  cross-Space grouping, search, keyboard navigation, and responsive layouts.
- Snoozing offers useful presets and automatically returns a due Chat to Active.
  Archiving and snoozing close an open tab, show an undo action, and never delete
  or rewrite the transcript.
- Deferred Chats open read-only and explain whether to **Resume** or **Restore**
  before another message can be sent.
- Lifecycle state is recorded as an append-only portable event in the Chat log.
  The local API rejects lifecycle changes during an active turn or compaction
  and independently rejects new messages until a deferred Chat is restored.
- Running indicators follow background turns across the Chat list and tab strip.
  A completed turn that settled out of view gains a quiet attention marker until
  that Chat is viewed. Attention acknowledgement stays machine-local.

## A more legible Assistant

- Typing `/` or opening the composer menu reveals Pi's authoritative catalog of
  installed Skills, prompts, Extension commands, and supported built-ins.
- The command menu is ranked and keyboard navigable, without hard-coded package
  names or a Workspace-only Skill format.
- The composer shows the active model and estimated context-window pressure,
  while distinguishing current context from total tokens processed across
  compacted history.
- Settings can start Pi provider OAuth flows that advertise native OAuth
  support. Workspace opens the system browser, presents device-code and
  manual-code prompts in desktop UI, and persists credentials through its
  existing encrypted Pi authentication host. Compatibility remains
  provider- and account-tier-specific rather than a blanket subscription claim.

## Reliability and release hardening

- `sharp`, `postcss`, `protobufjs`, `tar`, `fast-uri`, and `brace-expansion` are
  updated to reviewed security-fix versions.
- A fail-closed install normalization handles Pi's currently shrinkwrapped
  `brace-expansion` copy. Tests and desktop preflight require Pi to resolve the
  fixed 5.0.8 package before a release can be built.
- macOS release artwork generation and packaged CLI checks are more deterministic
  across clean release machines.

## Upgrade notes

This is an in-place update. Registered Spaces, ordinary files, Chats, Library
materials, History, Pi resources, provider settings, restricted apps, grants,
connections, automations, and App-platform state are preserved.

Existing Chat logs require no migration. A Chat remains Active unless and until
an archive or snooze event is appended. Background attention acknowledgement is
stored only on the current computer.

## Release verification posture

This document describes the 0.4.1 release candidate. Public release completion
requires the exact pushed `v0.4.1` commit to pass Node 24 TypeScript checks, the
full test suite, a high-severity dependency audit, desktop preparation and
preflight, Windows installer/updater verification, and the guarded signed and
notarized macOS publication lane. The installed 0.4.0 macOS app must then
discover and apply 0.4.1 through its visible updater control before the
end-to-end update is considered verified.
