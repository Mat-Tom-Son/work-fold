# Workspace 0.4.10

Workspace 0.4.10 makes restricted-app browser sign-in practical with real
providers while keeping every provider-controlled endpoint and parameter
inside the revision the user reviews.

## Provider-compatible OAuth, still pinned to the review

- Restricted apps can declare RFC 8414, OpenID Connect, or fully pinned OAuth
  discovery, plus a bounded set of static authorization parameters.
- Workspace accepts providers that under-advertise authorization-code, PKCE,
  or public-client support while continuing to enforce authorization code with
  S256 PKCE and no client secret itself.
- The review and installed-app access screens show the issuer, public client
  id, scopes, discovery mode, exact pinned endpoints, and extra authorization
  parameters before a browser sign-in is used.
- Provider metadata compatibility notes survive restarts and remain visible
  beside the connection instead of disappearing into developer logs.

## Honest restricted-runtime limits

- The sandbox now receives one host-composed limits contract for network,
  files, storage, notifications, and invocation payloads.
- Renderer-to-host envelopes are derived from the same effective request and
  storage limits, so a payload the API advertises as valid is no longer
  rejected early by a smaller transport ceiling.
- Oversized network bodies fail with the stable
  `NETWORK_REQUEST_TOO_LARGE` error before crossing the bridge.
- A packaged Electron sandbox smoke now verifies the live broker limit
  contract as part of desktop preparation.

## Upgrade notes

This is an in-place update. Registered Spaces, ordinary files, Chats, Library
materials, History, Pi resources, provider setup, appearance settings,
restricted apps, grants, saved connections, automations, open tabs, and
App-platform state are preserved.

## Release verification posture

Public release completion requires the exact pushed `v0.4.10` commit to pass
Node 24 TypeScript checks, the full test suite, dependency audit, desktop
preparation, the canonical Electron Builder package smoke, the Windows release
workflow, and the guarded Developer ID-signed, notarized, and stapled macOS
publication lane. The installed 0.4.9 macOS app must discover and apply 0.4.10
through the visible frontend updater, preserve existing state, pass installed
bundle verification, and survive a full quit and cold reopen.
