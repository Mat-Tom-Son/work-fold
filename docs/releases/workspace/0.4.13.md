# Workspace 0.4.13

Workspace 0.4.13 makes contributed Space apps feel like part of Workspace
instead of a web page laid over it.

## Consistent app canvases

- Navigator apps now use the same 12-pixel breathing room beneath the
  persistent Space header as Files, Chats, and History.
- The native Electron app surface is rounded by the host itself, so installed
  apps no longer paint square corners over the rounded renderer placeholder.
- The default 12-pixel radius applies to existing apps without changing their
  reviewed manifest or digest.
- App authors may optionally request a whole-pixel radius from 0 through 24 in
  `ui.cornerRadius`. The reviewed value applies consistently to navigator and
  app-owned tab surfaces.

## Authoring and safety

- Codex and Claude Code share the same documented `cornerRadius` primitive
  through the canonical contributor contract and app-authoring guidance.
- The radius is bounded, presentation-only metadata. It grants no network,
  file, notification, credential, automation, or host authority.
- The native host reads the value from the inspected manifest, not app
  JavaScript or renderer IPC.
- Omission remains the recommended compatibility path because older strict
  Workspace builds do not recognize the newer optional field.
- Electron's rounded cutout is visual rather than a hit-test boundary; the
  shell inset deliberately keeps the corner area over inert pane background.

## Upgrade notes

This is an in-place update. Registered Spaces, named Chats, ordinary files,
Library materials, History, Pi resources, provider setup, appearance settings,
restricted apps and their digests, grants, saved connections, automations,
open tabs, app data, and App-platform state are preserved.

## Release verification posture

Public release completion requires the exact pushed `v0.4.13` commit to pass
Node 24 TypeScript checks, the full test suite, dependency audit, desktop
preparation, the real-Electron restricted-app probe with an explicit 24-pixel
override, the canonical Electron Builder package smoke, the Windows release
workflow, and the guarded Developer ID-signed, notarized, and stapled macOS
publication lane. The installed 0.4.12 macOS app must discover and apply
0.4.13 through the visible frontend updater. Installed-app QA must verify both
an existing omitted-field app and an explicit radius override in navigator and
app-tab placements.
