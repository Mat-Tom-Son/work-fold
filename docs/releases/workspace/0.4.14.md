# Workspace 0.4.14

Workspace 0.4.14 hardens the restricted-app workflows exercised by the new
demo Spaces.

## Exact-file app grants

- Restricted apps can now atomically replace one explicitly mapped file using
  the documented grant-relative `path: "."` convention.
- The broker keeps its temporary file in the selected file's verified ordinary
  parent directory without widening app authority.
- Exact-file grants still cannot list siblings, create another filename,
  traverse links, reach Workspace metadata, or escape the owning Space.
- A focused regression test covers the real read-then-replace flow that exposed
  the issue in Reading Room.

## Clean app updates

- Updating or removing a restricted-app revision now closes work tabs owned by
  the obsolete digest after the installed-app catalog is known.
- Current-revision tabs remain open, and tabs for Spaces whose app catalog is
  still loading are preserved.
- Users no longer accumulate duplicate-looking app tabs whose older revision
  can only render an unavailable state.

## Demo-space dogfooding

The installed application was exercised with Service Bay, Field Desk, Seismic
Watch, Reading Room, Civic Briefing, and Trip Studio. Together they cover
loopback services, four public data providers, app-owned tabs, persistent app
storage, exact-file and directory grants, History-producing writes, static
notifications, scheduled workers, and Assistant-invoked app tools. That pass
also updated Trip Studio to Frankfurter's current public origin and fixed a
multi-service callback bug in Service Deck.

## Upgrade notes

This is an in-place update. Registered Spaces, named Chats, ordinary files,
Library materials, History, Pi resources, provider setup, appearance settings,
restricted apps and current digests, grants, saved connections, automations,
app data, and App-platform state are preserved. Tabs owned by a restricted-app
digest that is no longer installed are intentionally removed.

## Release verification posture

Public release completion requires the exact pushed `v0.4.14` commit to pass
Node 24 TypeScript checks, the 572-test suite, dependency audit, desktop
preparation, real-Electron restricted-app smoke, the canonical Electron Builder
package smoke, the Windows release workflow, and the guarded Developer
ID-signed, notarized, and stapled macOS publication lane. The installed 0.4.13
macOS app must discover and apply 0.4.14 through the visible frontend updater.
Installed-app QA must then replace an exact-file grant, confirm stale
old-revision tabs are removed, cold-launch all six demo Spaces, and rerun a
representative app worker and Assistant tool.
