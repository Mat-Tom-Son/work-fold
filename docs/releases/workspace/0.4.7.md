# Workspace 0.4.7

Workspace 0.4.7 turns Space appearance into a safer, more capable identity
system. People can shape a Space visually from one focused editor, while Codex
and Claude Code can prepare the same bounded, code-free proposal for review and
import.

## A clearer Customize Space experience

- The Space editor now shows light and dark previews together, with primary and
  optional secondary colours, compact banner patterns, safe raster images, and
  a searchable Fluent icon catalog.
- A semantic resolver derives separate roles for reading text, UI text, glyphs,
  fills, borders, focus decoration, indicators, and on-accent content. WCAG 2.2
  AA is the conformance floor and APCA provides a second perceptual gate.
- The audit checks foregrounds against both the ordinary surface and the final
  composited soft fill. Image and gradient regions remain clearly identified as
  requiring visual review.
- Undo retains the latest 20 edits for each Space during the current app
  session. Reset returns the Space to its default identity.
- Proposal import and export make a complete appearance easy to review and
  reuse without accepting CSS, JavaScript, or executable theme packages.

## Durable, local appearance

- Appearance now lives in versioned machine-local application state rather than
  remaining dependent on renderer local storage.
- Writes use restrictive temporary files, file and directory synchronization,
  atomic replacement where supported, and a last-known-good backup.
- Existing renderer-local appearance is imported once. The exact light-mode
  colours from the 12 shipped presets remain unchanged.
- Removing a Space removes its committed appearance after successful cleanup.
  Ordinary Space files and portable `.workspace/` identity data are not changed
  by appearance edits.

## One contract for people and agent harnesses

- `npm run --silent workspace:appearance` creates, validates, and resolves inert
  appearance proposals for both Codex and Claude Code.
- The command has no apply operation. A person chooses the target Space and
  imports the proposal through Customize Space, preserving the authenticated
  mutation boundary.
- The repository now includes the semantic role contract, an exhaustive current
  CSS consumer inventory, and shared product and contributor guidance.

## Known limits

- This release migrates the highest-obligation text, user-message, state, and
  customization surfaces. Remaining legacy accent aliases deliberately preserve
  their previous rendering while the role inventory guides later mechanical
  migration.
- Undo is session history, not a durable theme-version system.
- Contrast over arbitrary image pixels and gradient positions cannot be proven
  statically and remains an explicit visual-review item.
- Appearance is personal application state on this computer; it is not written
  into or synchronized with a Space folder.

## Upgrade notes

This is an in-place update. Registered Spaces, ordinary files, Chats, Library
materials, History, Pi resources, provider setup, restricted apps, grants,
connections, automations, and App-platform state are preserved. A valid legacy
Space appearance is imported non-destructively on first launch.

## Release verification posture

Public release completion requires the exact pushed `v0.4.7` commit to pass
Node 24 TypeScript checks, the full test suite, dependency audit, desktop
preparation, the canonical Electron Builder package smoke, the Windows release
workflow, and the guarded Developer ID-signed, notarized, and stapled macOS
publication lane. The installed 0.4.6 macOS app must discover and apply 0.4.7
through the visible frontend updater, preserve existing state, pass installed
bundle verification, and survive a full quit and cold reopen.
