# Workspace 0.5.0

Workspace 0.5.0 makes contributed apps and Assistant-tool administration feel
more deliberate, predictable, and native to the Workspace shell.

## Shell-owned app boundaries

- Restricted app canvases now keep a shell-owned guard beside the persistent
  rail. App pixels cannot begin at the rail edge, even when an app uses a
  negative-positioned handle or other edge treatment inside its canvas.
- Native app bounds are inset inside the renderer-owned border, preserving the
  host frame instead of painting over it.
- The rail has its own isolated stacking context for ordinary renderer
  components, while Electron's native app view remains physically bounded away
  from that chrome.
- Existing host-owned corner-radius clipping remains in place for navigator and
  app-owned tab surfaces.

## Clearer Assistant tools

- The Installed view now begins with one compact inventory summary showing the
  apps, Space tools, and Personal tools available in the current Space.
- Apps are presented before Skills and Extensions because their access,
  connections, and automations are managed per Space.
- Each app row now reports its useful access state—such as **Access off** or the
  number of enabled powers—instead of a generic runtime badge.
- Package sources and Pi's built-in tools move into collapsed **Supporting
  details**, keeping distribution plumbing available without competing with
  day-to-day management.
- The page uses a narrower reading measure, quieter metadata, clearer section
  spacing, and responsive layouts tested across full and narrow work panes.

## Authorization boundaries

This release changes presentation and native view geometry, not authority.
Restricted apps still install with network destinations, Space files,
notifications, saved connections, and every named automation off. Each power
remains a separate human decision in Assistant tools. Personal and This Space
Skills and Extensions retain their existing Pi scopes and full-trust behavior.

## Upgrade notes

This is an in-place update. Registered Spaces, named Chats, ordinary files,
Library materials, History, Pi resources, provider credentials and selection,
appearance settings, restricted apps and their reviewed digests, grants,
connections, automations, app data, Releases, and App Instances are preserved.
No manifest or data migration is required.

## Release verification posture

Public release completion requires the exact pushed `v0.5.0` commit to pass
dependency installation, TypeScript checks, the complete test suite,
high-severity dependency audit, desktop preparation, the real-Electron
restricted-app smoke, and the canonical Windows package workflow. macOS
publication additionally requires the guarded Developer ID-signed, notarized,
and stapled release lane after the matching source release is public. Installed
update verification must confirm the production bundle identity, public feed,
preserved Space/app state, and the rail boundary around contributed app
surfaces.
