# Workspace 0.5.1

Workspace 0.5.1 fixes contributed-app rail tooltips so the complete
shell-owned navigation stays visible above an app's native canvas.

## Rail tooltip visibility

- Hover and keyboard-focus tooltips now remain fully visible beside contributed
  apps instead of appearing as a clipped black edge.
- The native restricted-app view yields for the complete tooltip lifecycle:
  entrance, visible state, and exit fade.
- The app stays mounted while the tooltip is open, so its session and in-app
  state are preserved.
- The shell-owned rail guard introduced in 0.5.0 remains in place around every
  contributed-app surface.

## Authorization boundaries

This patch changes native view composition and tooltip timing only. Restricted
app grants, connections, automations, notifications, file access, and network
destinations remain separate human decisions in Assistant tools.

## Upgrade notes

This is an in-place update. Registered Spaces, named Chats, ordinary files,
Library materials, History, Pi resources, provider credentials and selection,
appearance settings, restricted apps and their reviewed digests, grants,
connections, automations, app data, Releases, and App Instances are preserved.
No manifest or data migration is required.

## Release verification posture

Public release completion requires the exact pushed `v0.5.1` commit to pass
dependency installation, TypeScript checks, the complete test suite,
high-severity dependency audit, desktop preparation, the real-Electron
restricted-app smoke, and the canonical Windows package workflow. macOS
publication additionally requires the guarded Developer ID-signed, notarized,
and stapled release lane after the matching source release is public.
