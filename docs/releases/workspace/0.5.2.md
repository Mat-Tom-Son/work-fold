# Workspace 0.5.2

Workspace 0.5.2 repairs contributed-app rail tooltips at the native-view
boundary and makes Assistant tools and app approval substantially easier to
understand.

## Rail tooltips without app blanking

- Rail tooltips above contributed apps now render in a small host-owned native
  overlay that remains physically above the app canvas.
- Showing a tooltip no longer hides, detaches, or remounts the contributed app,
  so app pixels, state, and interaction remain intact throughout hover and
  keyboard focus.
- The overlay accepts only bounded plain text, bounds, and light/dark theme
  input. It runs without JavaScript, images, Node integration, navigation, or
  developer tools.
- Real-Electron verification now mounts an app and tooltip together, re-lays
  out the app, reasserts overlay order, hides the tooltip, and proves the app
  remains attached at every step.

## Clearer Assistant tools

- Installed apps, Skills, and Extensions now share one search, scope, type, and
  sort toolbar with one result count.
- The page begins with a concise health summary and presents apps as part of
  the same tool inventory instead of as a visually disconnected subsystem.
- Empty and filtered states are quieter and more specific, while supporting
  package details remain available without dominating the page.
- Running Chats now say **Working**, and completed background replies say
  **New reply**, so active and attention-needed work can be recognized without
  decoding an unlabeled dot.

## Deliberate app approval

- App review separates the one current decision—adding the exact reviewed
  revision—from every access decision that may follow later.
- The review lists what is added immediately and presents network connections,
  chosen Space files, notifications, and automations as a linear permission
  ledger, each explicitly marked off when added.
- Installed app details begin with a compact access overview showing enabled
  and declared counts for each authority category.
- There is no preview flag or alternate approval path. The redesigned review is
  the product path, and obsolete review and tooltip-blanking implementations
  have been removed.

## Authorization boundaries and limitations

This release changes native view composition and management presentation, not
authority. Restricted apps still install with network destinations, Space
files, notifications, saved connections, and every named automation off. Each
power remains a separate human decision in Assistant tools. Skills and
Extensions retain their existing native Pi scopes and full-trust behavior.

The host-owned tooltip is intentionally limited to Workspace's persistent rail;
it is not a general surface that contributed apps can invoke or customize.

## Upgrade notes

This is an in-place update. Registered Spaces, named Chats, ordinary files,
Library materials, History, Pi resources, provider credentials and selection,
appearance settings, restricted apps and their reviewed digests, grants,
connections, automations, app data, Releases, and App Instances are preserved.
No manifest or data migration is required.

## Release verification posture

Public release completion requires the exact pushed `v0.5.2` commit to pass
dependency installation, TypeScript checks, the complete test suite,
high-severity dependency audit, desktop preparation, the real-Electron
restricted-app composition smoke, and the canonical Windows package workflow.
macOS publication additionally requires the guarded Developer ID-signed,
notarized, and stapled release lane after the matching source release is
public.
